# 管理后台与邮箱注册

管理员直接访问 `https://你的域名/#admin`，用户界面不显示入口。管理员账号与用户账号分开，两种 token 不能互相访问接口。服务器 URL 配置位于登录页最下方的折叠区。

## 首次启动

在 `.env` 设置 `ADMIN_USERNAME`（3–24 位小写字母、数字、下划线）和 `ADMIN_PASSWORD`（12–128 字符）。每次启动以这些值同步管理员身份；修改后通过 love 的部署配置应用，凭据变化会撤销管理员会话，值未变则保留会话。后台不修改管理员密码。会话有效 8 小时，保存在当前浏览器标签会话中。

默认关闭自行注册。首次登录后台后，可以直接创建用户，也可以先配置 SMTP、发送测试邮件，再启用邮箱注册。

| 注册方式     | 行为                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| 仅管理员创建 | 管理员填用户名、昵称、邮箱及初始密码，并确认该邮箱属于用户               |
| 邮箱注册     | 用户自行创建账号；图形与邮件验证码通过后才产生账号与登录会话             |
| 邮箱白名单   | 管理员添加完整邮箱；用户自己创建账号并验证邮箱，添加白名单本身不创建账号 |

“允许注册的邮箱域名”为空时不限制域名；填写后与白名单规则同时生效。提交注册时再次检查当前规则；发送验证码后被移出白名单不能继续注册。已注册用户不受随后更改的注册规则影响，需要禁止登录时停用账号。

图形验证码为 PNG 图片，绑定请求 IP、用途和 5 分钟期限，提交一次即失效，答错需刷新。用户与管理员登录、发送注册及找回密码邮件均需要验证码。邮件验证码为 6 位数字，10 分钟有效、最多尝试 5 次，成功使用后不能重放；同一邮箱同一用途两次发送至少间隔 60 秒。密码找回只接受找回用途的验证码，成功后撤销用户全部会话。接口另有 IP 频率限制。

## SMTP

设置主机、端口、传输方式、用户名、密码或授权码、发件地址及显示名称。465 通常使用 TLS，587 通常使用 STARTTLS，以服务商说明为准。明文方式适用于受信任的本地邮件中继。发件邮箱须符合服务商授权规则。

先保存，再向自己的邮箱发送测试邮件。“已交给 SMTP 服务器”表示 SMTP 接受发送，不等于最终送达，需检查收件箱及垃圾邮件。留空密码保留现有密码，勾选清除才移除。SMTP 密码使用 AES-256-GCM 加密保存，API 仅返回是否配置密码。`MEDIA_SIGNING_SECRET` 必须稳定并随数据备份；更换后重新填写 SMTP 密码与 AI Key。

## 管理能力

- 概览：账号、停用账号、配对、图片／视频、媒体容量、消息、回忆、近 24 小时请求与错误、AI 队列及通知状态。
- 账号：搜索、分页、创建、停用／恢复、撤销全部会话、重设密码。停用、撤销或重设密码会断开 Socket，关闭本地通知连接并撤销邀请码；恢复不会恢复旧 token。
- 配对与存储：双方、已归档空间、消息／媒体／回忆数、真实文件容量、默认及每对独立配额。
- 日志：访问、后台事件、管理员操作，支持搜索、分页、日期范围、HTTP 状态或后台等级筛选。
- 设置：注册方式、邮箱域名、白名单、SMTP、默认配额、日志保留天数。

容量按配对空间分配，包含聊天、相册、AI 头像上传的实际保留文件字节总和。两人可以在设置中开启仅保存压缩媒体；此后上传只计压缩预览与缩略图，默认同时保留原文件。个人头像使用独立接口，输入文件不设大小或像素上限，仅保留一张当前头像的 512/256 像素压缩版本，不占两人额度。MiB 按 1024² 字节计算。新配对默认分配 1024 MiB，创建时保存独立额度，之后修改默认值不会改变已分配额度。管理员可单独调整；0 禁止新增上传，留空将当前默认额度分配给该空间，之后默认值变化不会影响它。未分配独立额度的空间禁止上传，需管理员先分配。降低配额不删除文件，超过上限后禁止新增上传；最终入库前在事务中重新核验身份、当前配对及容量，超限清理本次文件。解除配对后的归档空间保留容量记录。

访问日志记录时间、方法、不含查询参数的路径、状态、耗时、请求 ID、IP、账号 ID、浏览器标识；不记录请求体、Authorization、验证码和媒体签名查询参数。后台日志记录启动、连接、拒绝与错误；操作记录追踪管理修改，不保存密码。保留期 7–90 天，每类最多 100,000 条，每分钟清理。启动失败等数据库外事件仍使用 `docker compose logs` 查看。

数据库迁移从版本 1 重新开始，001 保存当前完整表结构。启动时在事务和数据库锁保护下按顺序执行未应用的增量，并在 `schema_migrations` 中记录编号、名称、SHA-256 校验和及时间；迁移失败不启动应用。已发布增量不可修改。此前 schema 4～9、无迁移历史的数据库与旧备份不再支持，也不自动标记为版本 1。Docker 使用 `love-v4` 项目。详见 [部署文档](deployment.md)。

前台登录页与用户设置不提供管理后台入口。管理员自行访问 `https://你的域名/#admin`；隐藏入口只是界面要求，服务端 `/api/admin/*` 仍独立校验管理员会话，普通用户会话不能访问管理数据。

## 注册邀请码

设置中独立勾选“注册需要邀请码”，默认关闭。开启后，邮箱注册及邮箱白名单注册都需要邀请码，同时保留邮件验证、图形验证码、域名和白名单限制；管理员直接建号不需要邀请码。发送邮件验证码时先检查邀请码，提交注册时重新验证，并在同一事务中创建账号和消耗次数，失败不会占用邀请码。

后台“设置 → 注册邀请码”可每次生成 1–200 个，设置批次备注、每码 1–10000 次使用、有效期 0–3650 天（0 不过期）。生成后一次性显示完整邀请码，可下载包含 ID 和邀请码的 CSV，便于对应列表停用；离开页面后无法恢复明文。列表显示最近 1000 个邀请码的批次、用量、到期时间和状态，可停用。服务端只保存哈希，日志不记录邀请码。配对邀请与注册邀请码是两个独立功能。

运行 `./love` 只修改 `.env` 部署参数与管理员凭据，业务管理统一在后台进行，详见 [配置边界](configuration.md)。
