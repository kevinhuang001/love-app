# 架构

Love 的 Web 与 Android 共用 React 界面。Node.js 后端负责身份校验、业务数据、媒体处理、实时通信和 AI 调用。独立 `love` 管理程序运行在 Linux 宿主机，负责部署与数据库维护。

逐项运行过程与失败分支见[实现细节目录](implementation/README.md)。

## 组件与职责

| 组件           | 技术与职责                                                             |
| -------------- | ---------------------------------------------------------------------- |
| Web 客户端     | React、TypeScript、Vite、Tailwind CSS、shadcn/ui；页面与本地待发送队列 |
| Android 客户端 | Capacitor；共用 Web 界面，原生代码处理后台通知、文件下载与分享         |
| 后端           | Node 24、Express、Socket.IO；API、权限、任务和媒体访问                 |
| 数据库         | SQLite 或 PostgreSQL；通过统一异步 `DB` 接口访问                       |
| 媒体处理       | Sharp 与 FFmpeg；生成压缩预览、缩略图和视频封面                        |
| 日历模块       | `packages/calendar`；前后端和 AI 共用日期规则                          |
| 管理程序       | JavaScript、Clack、Bun 编译；生成配置、调用 Compose、备份与恢复        |
| 可选代理       | Caddy／Certbot 或已有代理；提供 HTTPS 和转发                           |

推荐单个后端进程部署。使用 PostgreSQL 并不自动获得多实例实时通信能力；水平扩展还需处理 Socket.IO 房间、在线状态、任务协调和通知连接的跨实例共享。

## 用户与两人空间

每个用户有独立账号；配对后两人共享 `coupleId` 对应的聊天、回忆、日程、容量和 AI 设置。解除配对会断开当前关联，原空间保留。

请求从会话解析用户及当前配对，不信任客户端提供的目标用户身份。未配对用户只能使用个人资料、配对与退出等接口。管理员使用独立账号和会话，普通用户 token 不能访问管理接口。

密码使用带随机盐的 scrypt。数据库只保存会话 token 的 SHA-256 摘要。验证码绑定用途并限制有效期和次数；SMTP 密码与 AI Key 使用服务密钥加密。修改权限规则时，既有 Socket 和通知连接也需要撤销。

## 消息流程

客户端经 HTTP 提交消息，后端先持久化，再向当前两人房间广播 Socket.IO 事件。`senderId + clientId` 唯一约束处理重复提交。客户端的待发送队列按服务器、账号和配对分开，切换身份不会混入另一处队列。

Socket 事件是及时更新的提示，数据库中的历史消息才是持久化来源。重连和回到前台时重新获取历史，恢复遗漏内容。在线状态由前台报告维护，后台通知连接不计入在线。

## 媒体流程

上传先接收、识别日期、生成预览，再暂存为未发布媒体。保存回忆、发送附件或设置头像时，重新检查身份、配对和额度，在事务中提交媒体、容量及业务记录。

失败或强制退出可能留下暂存内容，由维护功能清理。图片和视频通过带签名的 API 读取，不直接公开媒体目录；视频支持 Range 请求。输入不设统一的文件大小、像素或时长上限，但仍受配对总额度、处理资源和代理设置限制。

SQLite 使用磁盘媒体；PostgreSQL 使用数据库分块。两种实现由 `MediaRepository` 提供同一访问接口，详见 [数据库与媒体存储](database.md)。

## AI 执行

配对双方共享 AI 地址、模型、Key、名称和头像。聊天提到当前助手名后，后端将任务写入队列，再调用兼容 OpenAI 的模型服务。

AI 工具限定在发起者及其当前两人空间，不能执行通用 SQL、Shell 或文件操作。工具调用结果和调用 ID 持久化，以处理重启和重复请求。当前最多 5 轮，每轮最多 8 个工具调用。

本次图片以压缩数据提供给视觉模型，视频提供封面与时长。用户会话 token 不发给模型服务。请求和工具结果所涉及的私人数据会发给选定服务，因此客户端使用说明必须说明这个范围。

## Android 通知

原生前台服务用 Bearer token 连接 SSE 通知流，事件只包含消息编号。手机处理重连和本地提醒，通知正文不包含聊天内容。系统终止应用进程后没有第三方推送来唤醒它，需在真实手机验证电池与锁屏行为。

## 部署和升级

`love` 根据部署配置组合 Compose 文件，后端在启动阶段调用 `openDatabase` 迁移数据库。更新管理程序不应提前迁移仍运行旧版应用的数据；原生数据库维护要求管理程序与配置的应用镜像版本一致。

数据库迁移、媒体提交、备份恢复分别有自己的事务与失败处理，不能用一段部署脚本代替这些数据一致性约束。具体流程见 [迁移规范](migrations.md) 和 [备份格式](backup-format.md)。
