# 备份与相册文件格式

服务器备份用于恢复整个 Love 服务；相册 ZIP 用于导出或导入当前两人的回忆。两者格式和用途不同，不能互换。

## 服务器备份

由管理程序生成的目录包含以下文件：

| 文件             | 内容                                        |
| ---------------- | ------------------------------------------- |
| `deployment.env` | 来源部署配置，包含恢复加密凭据所需的密钥    |
| `data.tar.gz`    | gzip 压缩的 tar，内含数据库快照、媒体和清单 |
| `SHA256SUMS`     | 前两个文件的 SHA-256                        |

`data.tar.gz` 中有 `love.sqlite`、`media/` 和 `manifest.json`。来源即使是 PostgreSQL，也使用 SQLite 表达业务数据和迁移历史，媒体从数据库分块导出为文件。

清单字段：

| 字段                 | 含义                                         |
| -------------------- | -------------------------------------------- |
| `format`             | 固定 `love-backup`                           |
| `version`            | 备份格式版本，目前 1                         |
| `applicationVersion` | 生成备份的软件版本，`major.minor.patch`      |
| `schemaVersion`      | 快照的数据库迁移编号                         |
| `provider`           | 来源为 `sqlite` 或 `postgres`                |
| `createdAt`          | ISO 时间                                     |
| `databaseSha256`     | `love.sqlite` 文件摘要                       |
| `report`             | 表行数、媒体记录数／文件数／字节数及内容摘要 |

`report.sourceDigest` 覆盖按确定顺序读取的业务行、媒体文件摘要和自增序号。`transferTables` 指定正式业务表；暂存上传不作为正式内容恢复。自增序号保留删除记录后的高水位，恢复不能只用当前最大 ID。

SQLite 备份处理 WAL 一致性；PostgreSQL 导出使用 repeatable-read 事务和分批游标。服务器管理会暂停本部署应用，避免其写入媒体时产生不一致副本。其他共享同一数据库的写入进程需要由部署方协调。

## 导入顺序和版本约束

1. 验证外层校验文件和安全路径，解压到私有临时目录；拒绝链接、特殊文件、重复文件和路径穿越。
2. 检查备份应用版本及 schema 版本均不高于目标支持范围；验证清单、数据库 SHA-256 和迁移历史。
3. 验证数据库完整性、关联、业务摘要及媒体内容，随后才迁移较低版本快照。
4. 迁移成功后重新生成临时副本的清单，并核对当前结构和数据。
5. 仅使用备份中携带的配置或数据库密钥解密 AI／SMTP 凭据，再用目标密钥加密。
6. 最后恢复目标数据：PostgreSQL 事务导入并核对行与媒体；SQLite 暂存数据库和媒体，使用持久化日志切换文件。

原归档保持不变，当前部署配置不覆盖。密钥变化时清空依赖旧密钥的验证码和邮件验证记录。无法解密凭据必须先明确报告，由操作者选择取消或只重置失效凭据。

格式版本高于 1、缺清单、旧 PGDMP 和没有新迁移历史的快照均不支持。应用版本和 schema 版本是两个独立门槛，不能只比较最大迁移编号。

实现入口为 `database-backup.ts`、`database-restore.ts`、`database-backup-cli.ts` 和 `deploy/manager.mjs`。CLI 用于镜像内工具调用，用户维护入口仍是管理菜单。

## 完整相册 ZIP

相册清单使用 `format: love-album`、`version: 1`，与服务器备份的清单独立。ZIP 包含当前相册引用的照片／视频预览、缩略图及实际保留的原文件。

| 清单部分  | 主要字段                                                                             |
| --------- | ------------------------------------------------------------------------------------ |
| `media`   | id、kind、width、height、duration、createdAt、original（可为空）、preview、thumbnail |
| 文件对象  | 相对 path、bytes、sha256                                                             |
| `moments` | mediaId、title、date、createdAt、author                                              |

导入重建媒体 ID 和当前空间关联，由导入者发布。按当前保留策略决定是否保存包内原文件，并核算实际保留字节。相同 ZIP 内容摘要去重；完整校验失败时不保存回忆。

相册 ZIP 不恢复账号、会话、聊天或服务配置。普通照片 ZIP 则仅导出 JPEG 照片，不提供 Love 元数据或视频。具体 API 见 [接口参考](api.md#相册与日程)，操作步骤见 [使用指南](../user/guide.md#导出与导入相册)。
