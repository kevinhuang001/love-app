# 持久化上传与原子提交

协议入口：`POST /api/uploads` 建立固定 UUID 任务，`GET /api/uploads/:id` 返回连续已收到字节数；`PUT /api/uploads/:id/:part/:index` 接收 1 MiB 分片，包含 SHA-256；`POST /api/uploads/:id/complete` 处理与提交；`DELETE /api/uploads/:id` 取消未提交任务。所有操作鉴权，并按上传者与配对关系隔离。伙伴可访问已发布共享内容，但不能读取对方的临时上传分片。

分片先写临时文件，fsync 后原子重命名，目录也同步。完整大小和 SHA-256 校验通过才接受分片；同一编号重复分片必须具有相同内容。会话清单也采用原子文件替换。服务重启后重新扫描连续完整分片，不依赖只在内存中的进度。会话在持久化应用工作目录 `media/tmp/sessions`，外部 PostgreSQL 临时不可用时不丢失已传分片。过期未提交会话在启动时清理，保留七天。

最终处理从分片重组工作副本，保留分片直至提交确认。媒体、容量记录、PostgreSQL 分块绑定和相册回忆在同一事务中提交。固定任务 UUID 同时作为媒体/回忆 ID，重试先查提交证据，提交响应丢失也不会重复创建或计费。取消与提交共用任务锁：提交成功返回冲突，取消不删除已发布内容；尚未建立的任务也保存取消标记，避免迟到请求重新开始。任务锁在单个应用进程中工作，部署仍为单应用服务。

数据库没有新增业务表；传输会话属于可恢复临时文件，用户可见历史保存在客户端。现有媒体草稿、媒体、回忆与容量表仍按原有备份协议工作，不修改不可变迁移。上传协议的测试同时跑 SQLite 和真实 PostgreSQL，覆盖分片重试、进程恢复、文件破损、跨用户访问、提交回滚与重复请求。

浏览器把 File Blob 与任务在同一个 IndexedDB 事务中保存；任务在空间根组件的队列执行，不绑定相册页。Android 文件选择器获得持久 content URI 读取权，原生服务保存本地副本，私有原子日志维护状态；上传与提交完全由 Java 执行，WebView 暂停不影响传输。前台服务按用户点击启动，声明 dataSync、通知和有超时的 wake lock，超时时暂停并保存任务。账号切换暂停旧任务，退出清除后台凭据。

每次传输操作最多尝试 12 次（含首次），仅重试网络失败、408、429、5xx；断网等待不耗尝试次数，指数间隔上限 30 秒。永久权限、容量或格式错误立即显示。PostgreSQL 默认 8 次（含首次），配置上限 20 次；只读、连接与幂等分块/提交操作允许重试，不重放结果不明的普通业务写入。不能确认 COMMIT 时保留数据，等待证据核对后再决定重试。任务失败保留本地文件与远端分片，手动重试继续传。
