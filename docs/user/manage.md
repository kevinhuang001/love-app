# 日常维护

在部署目录运行 `./love` 打开管理菜单。数据库备份、恢复和清理需要读取本机数据卷，普通账户通常使用 `sudo ./love`。下面的操作均在服务器上进行。

## 哪些设置在哪里改

| 想修改的内容                                           | 去哪里改               |
| ------------------------------------------------------ | ---------------------- |
| 数据库地址、监听 IP、端口、HTTPS、管理员账号和密码     | `love` → 部署配置      |
| 注册方式、邮件服务、注册邀请码、存储额度、日志保留时间 | 网页管理后台 `/#admin` |
| 昵称、头像、配对、AI、是否保留原图和原视频             | 应用里的“我们”         |

保存部署配置后需要应用配置并启动，改动才会进入容器。修改管理员账号或密码会让旧的后台登录失效。业务设置在后台保存后即可生效。

## 更新软件

1. 在管理菜单选择“检查更新”。
2. 查看应用和管理程序的当前版本、最新版本。
3. 确认更新，按提示选择是否先备份。
4. 等待新版本启动并通过检查。

更新会保留部署配置和数据。数据库需要升级时，应用在启动过程中自动处理，不需要另执行迁移命令。`docker pull` 只下载镜像，启动新容器时才处理数据库。

管理程序使用 XZ 压缩下载，校验压缩包后自动解压，再校验程序并替换 `love`。解压或校验失败会保留原程序。解压需要系统 `xz` 工具（Debian / Ubuntu 包名 `xz-utils`）。旧版管理器首次升级到支持 XZ 的版本时仍下载未压缩程序，之后的更新使用 XZ。

下载失败时原应用仍可运行；新版本启动失败时，查看日志并修复后重新启动。管理程序没有版本回滚选项。更新前保留一份可用备份，尤其是重要的照片和视频。

如果提示应用和管理程序版本不一致，先完成两者更新，再进行备份、恢复或清理。

## 备份

选择 **数据库管理 → 备份数据与配置**。备份过程中本部署的应用会暂时停止，完成或失败后恢复原来的运行状态。

备份保存在 `love` 同级的 `backups/` 目录。每次备份是一个独立目录，包含：

```text
部署配置 deployment.env
数据归档 data.tar.zst
校验文件 SHA256SUMS
```

新备份使用 Zstandard 无损压缩，程序会自动处理；旧版的 data.tar.gz 也可以导入，不用手工解压或转换。

把整个备份目录复制到另一台机器或其他可靠存储上。只放在原服务器的备份不能防止服务器或硬盘损坏。

这是整台 Love 服务的备份，包含账号、聊天、相册、日程、后台设置、媒体和解密所需的配置。备份含密码和密钥，请按私人数据保管。相册页的 ZIP 导出只导出当前两人的相册，不能代替服务器备份。

## 恢复备份

**恢复会替换目标 Love 数据。** 如果目标已经有内容，先备份目标。目标服务器的当前访问地址、数据库连接和管理员配置会保留。

1. 配好目标服务器的数据库，使用与备份相同或更新的软件版本。
2. 选择 **数据库管理 → 恢复备份**。
3. 从列表选择备份，或选择“指定备份目录路径”，填写整个备份目录的路径。
4. 检查恢复预览中的用户、聊天、相册和日程数量。
5. 确认后输入 `RESTORE`，等待完成。

恢复会校验备份内容，并自动把较低版本的数据升级到目标版本。**高版本软件生成的备份不能导入低版本软件。** 损坏、缺文件或版本不支持的备份会停止导入。

如果备份缺少正确的密钥，程序会列出无法解密的 AI Key 或邮件密码。可以取消，也可以选择恢复其他内容并清空这些失效凭据，再到应用或后台重新填写。图片和视频不依赖这些 AI／邮件密码。

首次配置 SQLite 或内置 PostgreSQL 时，也可以直接选导入备份，恢复完后再启动应用。

### 旧备份的限制

当前数据库体系以迁移版本 1 为起点。此前 schema 4～9 的数据库、旧 PGDMP 备份和没有新版本清单的备份不受支持。旧数据不会被自动当作版本 1，也不能通过改文件里的版本号获得兼容。这条限制适用于本次迁移体系重构之前的数据；之后从版本 1 开始的备份按上面的升级规则处理。

## 换服务器或换数据库

SQLite 和 PostgreSQL 之间可以通过备份恢复转换，步骤相同：

1. 在原部署生成完整备份。
2. 配置目标部署，选择目标数据库。
3. 在目标部署导入备份。
4. 检查账号、聊天和媒体，再让双方改用新访问地址。

仅修改数据库选项不会搬迁数据。接入外部 PostgreSQL 时，程序直接连接填写的数据库；已有 Love 数据会被使用，不自动拿本机数据去覆盖它。

## 检查与清理空间

“数据库管理”中的一致性检查用于查找缺失媒体、无效关联或容量记录异常。常规检查速度较快，深入检查还会逐个读取媒体并核对内容。

“清理未使用媒体”会先展示待删除内容，再让你确认。它清理没有用于聊天、回忆或头像的媒体，以及未完成发布的上传。正在使用的头像和已引用媒体会保留。清理前也可以选择备份。

PostgreSQL 删除媒体后，释放的空间会供数据库复用，磁盘上的数据库文件不一定马上变小。

## 停止与卸载

停止应用不会删除数据。卸载默认也会保留数据和备份；选择删除数据卷时，需要额外输入确认文字。

普通更新不要删除数据卷，也不要用 `docker compose down -v`。重新安装管理程序不能找回已经删除且没有备份的数据。

## 部署目录要保留什么

保留整个部署目录，尤其是 `love`、`.env` 和 `backups/`。管理程序会在自己的目录旁创建 Compose、代理等配置文件。应用数据通常在 Docker 数据卷里，因此仅复制部署目录不等于备份完整数据；搬迁应使用上述备份功能。
