# 常见问题

先在服务器运行 `love`，查看“状态与版本”和“查看日志”。记下完整错误再排查；删除数据库或数据卷通常不能解决连接问题，还会丢失内容。

## 手机或浏览器打不开

- 确认应用已经启动，状态为正常运行。
- 检查访问地址和端口。手机不能填写 `localhost` 或 `0.0.0.0`。
- 局域网直接访问时，HTTP 监听通常选 `0.0.0.0`；`127.0.0.1` 只允许服务器本机访问。
- 公网访问还需检查云安全组、防火墙、域名解析和反向代理。
- IPv6 地址需要方括号，例如 `http://[IPv6地址]:3000`，并确保手机网络和服务器都能通过 IPv6 互通。

可以在客户端登录页的“服务器设置”使用“测试连接”。同一地址在服务器上可访问但手机不通，优先检查网络路径和监听范围。

## 日志显示数据库连接超时

先从服务器宿主机检查数据库地址和端口是否可达。Love 容器还必须能访问这条网络路径；宿主机能连，不代表容器一定能连。

外部 PostgreSQL 地址中用户名、密码、主机、端口和数据库名都要正确。密码包含 `@`、`:`、`/` 等特殊字符时需要 URL 编码。数据库也必须允许来自 Love 服务器的连接。

使用 Tailscale 等私网地址时，确认两端在线、路由和访问规则允许数据库端口。检查服务器上是否配置了影响该连接的代理。

## 内置 HTTPS 一直没就绪

检查域名是否解析到服务器，公网 TCP 80 和 HTTPS 端口是否开放、是否被其他程序占用。配置了 AAAA 记录时，也要确保 IPv6 路径可用。

Certbot 失败时会记录原因并稍后重试。先根据日志修复 DNS 或端口问题。如果已有反向代理，应在部署向导选“已有反向代理”，避免两套服务争用端口。

## 不能注册或登录

默认关闭自行注册，请管理员创建账号。开放注册后还需符合邮箱域名、白名单和邀请码规则，并完成邮件验证。

图形验证码使用后会失效，失败后刷新再试。邮件验证码用于注册和找回密码的用途不同，不能互换。普通用户账号不能登录管理后台；管理员账号也不能当作聊天账号。

## 收不到验证邮件

管理员先在后台发送测试邮件，检查 SMTP 主机、端口、加密方式、账号与授权码。检查垃圾邮件和服务商退信记录。

“发送成功”表示 SMTP 服务接受了邮件，不保证已经送达收件箱。连测试邮件也失败时，先修复 SMTP，再开放邮箱注册。

## 照片或视频上传失败

查看剩余空间和服务器日志。两人空间额度不足时，请管理员调整额度或清理内容。很大的视频还需要服务器有足够的临时磁盘空间和处理时间。

使用自己的反向代理时，要允许上传大小和处理时间；Nginx 默认限制可能比 Love 的设置更严格。配置示例见 [手工部署](../developer/deployment.md#接入已有反向代理)。

没有识别出拍摄日期不等于上传失败，按界面提示填写即可。

## 提示磁盘空间不足

检查服务器磁盘、Docker 镜像和数据卷的占用。在 Love 数据库管理里预览并清理未使用媒体，更新成功后管理程序也会清理不再使用的旧 Love 镜像。

不要把 `docker volume prune` 或删除全部 Docker 资源当作普通清理命令。执行任何会删除数据卷的操作前，先确认完整备份保存在另一处。

## 备份不能导入

确认拿到的是整个服务器备份目录，包含 `deployment.env`、`data.tar.zst`（旧版为 `data.tar.gz`）和 `SHA256SUMS`。相册 ZIP 是普通照片和视频，不支持导入，也不能恢复服务器。

目标软件版本不能低于备份版本。缺失媒体、内容校验失败、旧格式或不支持的数据库结构会停止导入。兼容范围见 [日常维护](manage.md#旧备份的限制)。

## AI 没有回复

确认助手已启用，名字、服务地址、模型和 Key 都填写正确。聊天中需要提到当前名字，例如 `@小爱`，名字后接空格或标点。

服务需兼容 OpenAI Chat Completions 并支持工具调用；识图还需要视觉模型。使用内网 AI 服务时，由服务器管理员配置允许访问的主机，见 [配置参考](../developer/configuration.md#ai-与访问控制)。

## Android 后台通知不及时

检查通知权限、电池策略、后台运行权限以及网络。应用进程被系统关闭后不能自动远程唤醒；重新打开 Love 恢复连接。通知限制见 [Android 使用](android.md#通知有什么限制)。

## 外部 PostgreSQL 提示“数据库没有迁移历史”

如果这是此前 Love 创建、旧标记为 `database_meta=9` 的数据库，可以使用[一次性迁移 SQL](../../tools/database/postgresql-legacy-v9-to-schema1.sql)。先停止 Love，在 DBeaver 中连接这个数据库，执行整个文件；默认表位于 public，其他 schema 修改文件顶部 search_path。看到“迁移完成”后启动 Love。脚本检查不通过时不要手动伪造历史记录，应先查清版本和字段差异。业务数据保留，脚本不会清空数据库。
